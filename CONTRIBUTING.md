# Contributing

Contributions should make the roadmap easier to follow, more technically accurate, or more useful in practice.

## Suggested workflow

1. Open an issue describing the gap or improvement.
2. Keep each pull request focused on one module or concern.
3. Preserve the standard module structure: outcomes, topics, study path, exercise, checkpoint, and completion criteria.
4. Prefer durable concepts and official documentation over tool-specific tutorials.
5. Check all relative links and preview changed Markdown before submitting.

## Style

- Use clear, direct English and short paragraphs.
- Define an acronym on first use.
- Explain trade-offs, not only benefits.
- Mark vendor-specific examples as examples, not universal defaults.
- Do not claim “exactly once” delivery without defining the boundary and assumptions.
